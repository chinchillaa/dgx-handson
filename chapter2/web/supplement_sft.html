SFT と LoRA の仕組み

Supervised Fine-Tuning を低メモリで実現する手法

1

SFT とは何か

事前学習済み LLM は「次のトークンを予測する」という汎用タスクで学習されています。 これをユーザーの指示に従う形式へ変換するのが Supervised Fine-Tuning (SFT) です。

SFT の目的

フェーズタスク学習シグナル
事前学習次トークン予測大量のテキスト（教師なし）
SFT指示への回答生成（指示, 回答）ペア（教師あり）

SFT の損失関数は事前学習と同じ クロスエントロピー損失。違いは学習データが「回答トークン」のみに絞られていること。

SFT のプロンプトテンプレート例（Alpaca 形式）:

### 指示:
Pythonでリストをソートする方法を教えてください。

### 回答:
Pythonでリストをソートするには sorted() 関数または .sort() メソッドを使います...
2

LoRA の原理

LLaMA 3 8B の全パラメータ（約80億個）を更新すると、A100 80GB でもぎりぎりのメモリを消費します。 LoRA (Low-Rank Adaptation) はほとんどのパラメータを凍結し、 わずかな「差分行列」だけを学習することで、少ないメモリでファインチューニングを実現します。

LoRA の数式

元の重み行列 $W \in \mathbb{R}^{d \times d}$ に対して、差分を低ランク分解で表現します:

$$\Delta W = BA \quad (B \in \mathbb{R}^{d \times r},\ A \in \mathbb{R}^{r \times d},\ r \ll d)$$

推論時の出力:

$$h = Wx + \frac{\alpha}{r} \Delta W x = Wx + \frac{\alpha}{r} BAx$$

$r$ = rank（小さいほどパラメータ少、精度低）
$\alpha$ = スケール係数（通常 $\alpha = 2r$）

パラメータ数の比較

手法学習パラメータ比率メモリ（概算）
フルファインチューニング8,000,000,000100%~160GB
LoRA (rank=64)~40,000,000~0.5%~18GB
LoRA (rank=16)~10,000,000~0.1%~12GB

rank の選び方

  • • r=8〜16: 通常のタスク適応（推奨スタート地点）
  • • r=32〜64: 複雑なタスクや精度が重要な場合
  • • r=128+: ほぼフルファインチューニングに近い挙動
3

4bit 量子化 + LoRA = QLoRA

ベースモデルを 4bit で量子化（QLoRA）することで、さらにメモリを削減できます。 本ハンズオンでは BitsAndBytesConfig を使った NF4 量子化を採用します。 

from transformers import BitsAndBytesConfig

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_use_double_quant=True,   # 量子化定数をさらに量子化
    bnb_4bit_quant_type="nf4",        # Normal Float 4bit
    bnb_4bit_compute_dtype=torch.bfloat16,
)

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Meta-Llama-3-8B",
    quantization_config=bnb_config,
    device_map="auto",
)
