DPO の理論と preference data

フィードバックから応答スタイルを学習する手法

1

RLHF vs DPO

人間のフィードバックを学習に反映する方法として RLHF が広く知られていますが、 報酬モデルの学習と PPO という強化学習が必要で、実装が複雑です。 報酬モデルとは「この回答は何点か」を予測する別モデル、PPO はその点数が高くなるようにモデルを更新する強化学習アルゴリズムです。 DPO はこれを大幅に簡略化した手法です。 たとえば「回答Aより回答Bの方が親切」という比較例を見せて、モデルがBのような回答を出しやすくなるよう直接調整します。

参照モデルとは

参照モデルは学習対象のモデルが元の自然な言語出力能力を失ったり、極端な応答を生成したりすることを防ぐために、基準として比較・固定されるベースラインモデルのことです。
多くの場合、DPO を始める前の SFT 済みモデルをコピーして固定します。
学習中のモデルが評価基準通りの回答(chosen)を出しやすくなったかと、評価基準通りでない回答(rejected)を出しにくくなったかを、この固定モデルと比べて判断します。

たとえば、学習中モデルが chosen を強く好むようになっても、同時に元の自然な日本語や基本知識まで崩れてしまうと困ります。 そこで参照モデルは「元のモデルから離れすぎていないか」を測るものさしとして働きます。

手法必要なもの複雑さ安定性
RLHF (PPO)報酬モデル + PPO 実装 + 参照モデル高不安定になりやすい
DPOpreference データ + 参照モデル低安定

DPO は「報酬モデル不要」「強化学習不要」。通常の教師ありファインチューニングとほぼ同じ手順で実行できます。

2

DPO の目的関数

DPO の損失関数は以下の形をとります。 chosen（好ましい）回答の確率を上げ、rejected（好ましくない）回答の確率を下げます。 数式は長く見えますが、読むべきポイントは「同じ質問に対して、良い回答を悪い回答より出しやすくする」ことです。

$$\mathcal{L}_{\text{DPO}}(\pi_\theta) = -\mathbb{E}_{(x, y_w, y_l)} \left[\log \sigma \left( \beta \log \frac{\pi_\theta(y_w | x)}{\pi_{\text{ref}}(y_w | x)} - \beta \log \frac{\pi_\theta(y_l | x)}{\pi_{\text{ref}}(y_l | x)} \right) \right]$$

$\pi_\theta$：学習中モデルが持つ確率分布。$\pi_\theta(y|x)$ は「入力 $x$ に対して回答 $y$ を出す確率」を表す

$\pi_{\text{ref}}$：参照モデルが持つ確率分布。通常は SFT 済みモデルを固定して使う

$y_w$：chosen（好ましい回答）、$y_l$：rejected（好ましくない回答）

$\beta$：KL ペナルティ係数（参照モデルからの逸脱を制御）。大きいほど「元のモデルから変わりすぎないで」というブレーキが強くなります。

直感的な理解
参照モデルと比べて「chosen の確率の上昇幅」が「rejected の確率の上昇幅」を上回ればロスが下がります。 たとえば同じ質問に対して、丁寧で具体例のある回答を chosen、短く不正確な回答を rejected とすると、DPO は前者を選びやすくします。 $\beta$ が大きいほど参照モデルへの保守性が強くなります（過剰適応を防ぐ）。

数式を左から読む

1

参照モデルとの比率を見る

学習中モデルが、参照モデルより chosen / rejected をどれだけ出しやすいかを比べます。

πθ(y|x) / πref(y|x)
2

chosen と rejected を比べる

chosen 側の伸びから rejected 側の伸びを引きます。chosen の方が伸びていれば良い方向です。

log chosen比率 - log rejected比率
3

損失に変換する

差が大きいほど「良い学習」とみなし、損失が小さくなる形へ変換します。

-log σ(差)
記号読み方
πθ(y|x)学習中モデルの確率分布。入力 x に対して回答 y を出す確率
πref(y|x)参照モデルの確率分布。通常は SFT 済みモデルを固定して使う
yw / ylyw は chosen、yl は rejected
E1件だけでなく、データセット全体で平均するという意味

chosen の例

参照モデル 40% → 学習中モデル 60%

0.60 / 0.40 = 1.5

この例では1より大きいので、chosenを出しやすくなったと言えます。

rejected の例

参照モデル 35% → 学習中モデル 20%

0.20 / 0.35 ≒ 0.57

この例では1より小さいので、rejectedを出しにくくなったと言えます。

各記号の補足
log
確率の比率を足し引きしやすくします。回答全体の確率は非常に小さいため、ログ確率で扱う方が安定します。
σ（sigmoid）
chosen と rejected の差を 0〜1 のスコアに変換します。chosen が優勢なほど 1 に近づきます。
β
参照モデルから離れすぎないためのブレーキです。小さいと好みを強く反映し、大きいと保守的になります。

数値で見る DPO の動き

次の例では、質問「Python の sort() と sorted() の違いは？」に対して、 具体例つきの回答を chosen、短すぎる回答を rejected とします。 参照モデルは chosen を 40%、rejected を 35% の確率で出す状態から始まります。 DPO 後は chosen をより出しやすく、rejected を出しにくくします。

3

Preference データセットの作り方

DPO に必要なデータは （prompt, chosen, rejected）の3つ組 です。 prompt は質問、chosen は選んでほしい回答、rejected は避けたい回答です。 質より量よりも、chosen と rejected の差が明確 であることが重要です。 たとえば「具体例がある」「制約を説明している」「誤解を招かない」など、良い理由がはっきり分かるペアにします。

例: コード説明タスク

✓ chosen（良い回答）

「sorted() は元のリストを変更せず新しいリストを返します。一方 .sort() はリスト自体を変更し None を返します。...（具体的な例とコードを含む）」

✗ rejected（悪い回答）

「sorted か sort 使えばいいです。どちらも同じです。」

JSON フォーマット（scripts/train_dpo.py に渡す形式）

[
  {
    "prompt": "Pythonでリストを逆順にする方法を教えてください。",
    "chosen": "Pythonでリストを逆順にするには主に2つの方法があります...",
    "rejected": "reverse を使います。my_list.reverse() と書けばなります。"
  }
]

データ作成時の注意

  • • 5〜10件でも学習できます（本番は数百〜数千件推奨）
  • • chosen と rejected の差は明確にする（あいまいなペアは避ける）
  • • rejected は「完全に誤り」ではなく「やや不十分」程度の方が学習効果が出やすい
4

beta パラメータの実験

beta 値挙動リスク
0.01〜0.05参照モデルから大きく逸脱できる崩壊（同じ語の反復や意味不明な出力）のリスク
0.1（推奨）バランスの良い調整—
0.3〜0.5参照モデルに近い挙動を保つpreference（好みの比較例）が反映されにくい
