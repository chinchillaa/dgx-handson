評価指標の使い分け

BERTScore・ROUGE・LLM-as-judge の特性と使い所

1

3つの評価指標の概観

指標計算方法参照回答特徴
ROUGEN-gram の重複率必要計算が速い・意味を見ない
BERTScoreBERT 埋め込みのコサイン類似度必要意味的な類似を評価
LLM-as-judgeLLM による採点不要も可人間評価に最も近い

3つを組み合わせて使うのが原則です。ROUGE だけでは「同じ意味を別の表現で答えた」ケースが低く評価されます。 LLM-as-judge だけでは API コストがかかり、バイアスが入ります。

2

ROUGE

主に翻訳・要約の評価で使われる N-gram ベースの指標です。 生成文と参照文の間で共通する N-gram の割合を測ります。

ROUGE-L（最長共通部分列）の定義

$$\text{ROUGE-L} = \frac{2 \times \text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}$$

Precision: 生成文中に参照文と共通する LCS の割合 / Recall: 参照文中に生成文と共通する LCS の割合

from rouge_score import rouge_scorer

scorer = rouge_scorer.RougeScorer(["rouge1", "rouge2", "rougeL"], use_stemmer=False)

reference = "機械学習は大量のデータからパターンを学習するAIの手法です"
hypothesis = "機械学習はデータからパターンを見つけ出すAI技術です"

scores = scorer.score(reference, hypothesis)
print(f"ROUGE-1: {scores['rouge1'].fmeasure:.3f}")
print(f"ROUGE-2: {scores['rouge2'].fmeasure:.3f}")
print(f"ROUGE-L: {scores['rougeL'].fmeasure:.3f}")
3

BERTScore

BERT の埋め込み表現を使って、トークンレベルの意味的な類似度を計算します。 「同じ意味を異なる単語で表現した場合」に ROUGE より高いスコアを与えます。

BERTScore の計算方法（概略）

  1. 生成文・参照文の各トークンを BERT でベクトル化
  2. 各トークンペアのコサイン類似度を計算
  3. Recall: 参照文の各トークンが生成文の最も近いトークンとどれだけ似ているか
  4. Precision/Recall の F1 を最終スコアとする
from bert_score import score

references  = ["機械学習は大量のデータからパターンを学習するAIの手法です"]
hypotheses  = ["機械学習はデータからパターンを見つけ出すAI技術です"]

P, R, F1 = score(hypotheses, references, lang="ja", verbose=True)
print(f"BERTScore F1: {F1.mean().item():.3f}")
4

LLM-as-judge

LLM 自体に採点させる手法です。人間の評価者に最も近い結果が得られますが、 採点の再現性と LLM バイアスに注意が必要です。

採点プロンプトのテンプレート

あなたは公平な評価者です。以下の質問に対する回答を1〜5点で採点してください。

【質問】
{question}

【参照回答】
{reference}

【評価対象の回答】
{generated}

採点基準:
5: 参照回答と同等以上の正確さと詳しさ
4: ほぼ正確だが一部不足
3: 概ね正しいが重要な情報が欠けている
2: 部分的に正しいが誤りを含む
1: 明らかに誤りまたは無関係

スコア（1〜5の整数のみ）:

LLM-as-judge の注意点

  • • 自分自身の出力を高く評価する「自己バイアス」が知られている
  • • 長い回答を短い回答より好む傾向がある
  • • 複数回実行して平均を取ることで安定性が上がる
5

実験での使い分け指針

目的推奨指標理由
大量データの一次スクリーニングROUGE高速・参照文があれば低コスト
言い換えを含む意味的な評価BERTScore同義表現を適切に評価
最終的な品質判断LLM-as-judge人間評価との相関が高い
手法間の総合比較3指標の平均単一指標のバイアスを打ち消す
