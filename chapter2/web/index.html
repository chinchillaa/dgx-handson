この章の到達目標

  • ✓ タスクに応じて SFT・DPO・RAG を使い分けられる

  • ✓ RAG パイプラインを構築し、チャンクサイズの影響を体感できる
  • ✓ BERTScore・ROUGE・LLM-as-judge で手法間の差を定量比較できる

手法選定の判断フレームワーク

第2章の全トピックを始める前に、「どの手法をいつ使うか」を確認しておきます。 実験中に迷ったらこのフレームに立ち戻ってください。

Q1: タスク固有の知識が必要か？
→ YES → Q2: 知識は動的（頻繁に更新）か？
→ YES → RAG（ドキュメントを外部DBに置く）
→ NO → SFT が有力（知識をモデルに焼き込む）
→ NO → Prompt Engineering または DPO（応答スタイル調整）
§

セクション一覧

2-1 SFT (Supervised Fine-Tuning) + LoRA GPU必須 約90分

LLaMA 3 に LoRA アダプタを適用し、日本語指示データセットで SFT を実行します。 LoRA の rank・alpha を変えて学習コストと品質のトレードオフを観察します。

📄 補足: SFT と LoRA の仕組み 📓 ch2_01_sft.ipynb
2-2 DPO (Direct Preference Optimization) GPU必須 約60分

chosen/rejected ペアのデータセットを自分で作成し、DPOTrainer で学習します。 SFT モデルと DPO モデルの出力を並べて応答スタイルの差を確認します。

📄 補足: DPO の理論と preference data 📓 ch2_02_dpo.ipynb
2-3 RAG (Retrieval-Augmented Generation) CPU可 約60分

LangChain + ChromaDB でドキュメント検索パイプラインを構築します。 チャンクサイズ（256/512/1024 token）と top-k 件数を変えて検索精度を比較します。

📄 補足: RAG パイプラインの構成要素 📓 ch2_03_rag.ipynb
2-4 評価実験：手法を定量比較する CPU可 約45分

同一質問セット（10問）に対して「素のLLM」「SFT後」「RAGあり」で回答させ、 BERTScore・ROUGE・LLM-as-judge の3指標で採点・比較します。

📄 補足: 評価指標の使い分け 📓 ch2_04_evaluation.ipynb
