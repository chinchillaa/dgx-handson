# 参加者向け 接続手順書

このハンズオンでは、DGX（NVIDIA DGX Spark）1台を最大10人で共有します。
環境構築は不要です。運営側で1人1つずつ JupyterLab を用意しているので、貸与された VM から SSH でつないで、VM のブラウザで開くだけで始められます。

## 接続の流れ

```
会社の PC ──（会社の VM 接続の方法）──▶ 貸与 VM（1人1台）──（SSH）──▶ DGX
                                        └ ブラウザもこの VM の中で使う
```

- **DGX には、貸与された VM からしか接続できません。** 会社の PC や自宅のネットワークから直接 SSH しても、途中で遮断されてつながりません
- 以下の手順 1〜4 は、**すべて VM の中で**行います

## 事前に用意するもの

- **会社の PC**（貸与 VM にログインできること）
- **運営から受け取る情報**（1人ずつ異なります）

| 項目 | 例 |
|---|---|
| 参加者番号 | `p01` |
| 貸与 VM | p01 なら1号機（10.1.3.221）… p10 なら10号機（10.1.3.230）。ログイン方法は運営からお知らせします |
| SSH コマンド | `ssh -L 8801:localhost:8801 -L 8800:localhost:8800 handson@10.1.3.220` |
| JupyterLab の URL | `http://localhost:8801/lab?token=xxxxxxxx`（SSH でログインすると表示されます） |
| 教材ページの URL | `http://localhost:8800/`（全員共通） |
| SSH のパスワード | 運営から別途お知らせします |

> **URL（トークン）は自分専用です。** 他の人には教えないでください。知られると、あなたの JupyterLab を他の人が開けてしまいます。

## 接続手順

### 0. 貸与 VM にログインする

会社の PC から、運営に案内された方法で、自分に割り当てられた VM にログインします。以降の手順はすべて、この VM の中で行います。

### 1. SSH トンネルを張る

**VM の中で**ターミナル（Windows なら PowerShell）を開き、受け取った SSH コマンドを実行します。

```bash
ssh -L 8801:localhost:8801 -L 8800:localhost:8800 handson@10.1.3.220
```

`-L` が2つあるのは、JupyterLab（8801。番号は人によって違います）と教材ページ（8800。全員共通）の2つをつなぐためです。

- 初めて接続するときは `Are you sure you want to continue connecting (yes/no)?` と聞かれるので、`yes` と入力します
- パスワードを入力すると、次のように**自分専用の URL** が表示されます。これで接続成功です

```
================================================================
  DGX ハンズオン: 接続に成功しました
================================================================

  あなたの参加者番号: p01

  次の2つの URL を、この VM のブラウザで開いてください。

  JupyterLab : http://localhost:8801/lab?token=xxxxxxxx
  Web page   : http://localhost:8800/
```

- 参加者番号が自分の番号と違うときは、講師に声をかけてください（VM を取り違えている可能性があります）
- このあと入力はできません（DGX のコマンドは打てません）。それで正常です
- **このウィンドウはハンズオンの間ずっと開いたままにしてください。** 閉じると接続が切れます

### 2. ブラウザで開く

**VM の中のブラウザで**、手順 1 で表示された JupyterLab の URL を開きます（SSH のウィンドウで URL を選んでコピーし、ブラウザのアドレス欄に貼り付けます）。会社の PC のブラウザでは開けません（SSH トンネルは VM の中に張られているためです）。

```
http://localhost:8801/lab?token=xxxxxxxx
```

JupyterLab が開き、左側に `chapter1` `chapter2` `chapter3` のフォルダが表示されれば準備完了です。

### 3. 教材ページを開く

ブラウザの別のタブで、次の URL を開きます。講義の説明や補足資料はここで読みます。

```
http://localhost:8800/
```

> 教材ページは JupyterLab の中では開けません（JupyterLab の中で HTML を開くと、数式やリンクが正しく表示されないためです）。必ずこの URL から開いてください。

### 4. ノートブックを開く

JupyterLab の左側のファイル一覧から、講師の指示に従ってノートブック（例: `chapter1/notebooks/ch1_01_linear_regression.ipynb`）を開きます。カーネルは自動で選ばれるので、選ぶ必要はありません。

---

## VS Code は使わないでください

接続には、手順 1 の SSH コマンドを使ってください。VS Code の Remote-SSH では DGX に接続できません（安全のため、DGX へのトンネルを JupyterLab と教材ページの番号だけに制限しているためです）。

VM で VS Code を別の用途で開いている場合も、DGX につないだままにしないでください。VS Code の自動ポート転送が手順 1 と同じ番号を使ってしまい、手順 1 が失敗します。

---

## ハンズオン中のルール

- **自分の番号のフォルダ以外は触らないでください。** 全員が同じアカウントを使っているため、他の人のファイルを消せてしまいます
- **パッケージのインストール（`pip install` など）はしないでください。** 環境は全員で共有しています。必要なものはすべて入っています
- **モデルのダウンロードはできません。** 使うモデルは運営側で準備済みです。教材にないモデルを使いたいときは、講師に相談してください

---

## 知っておくと安心なこと

### ブラウザを閉じても、SSH が切れても大丈夫

ノートブックはサーバー側で動いているので、ブラウザを閉じたり SSH が切れたりしても、作業内容と実行中の処理は残ります。手順 1〜2 をやり直せば、続きから再開できます。

### 30分放置するとカーネルが止まる

30分何も実行しないと、メモリを空けるためにカーネルが自動で止まります。ファイルは残りますが、変数は消えます。「`NameError: name 'model' is not defined`」のようなエラーが出たら、**セルを上から実行し直してください。**

### 1人あたりのメモリには上限がある

他の人の作業を止めないよう、1人あたりのメモリには上限があります。

- `OutOfMemoryError` が出たら、メニューの **Kernel → Restart Kernel** でカーネルを再起動し、batch size などを小さくして実行し直してください
- カーネルが突然止まった（「Kernel Restarting」と表示される）ときも、メモリの使いすぎが原因の可能性があります

### 第2章の学習は順番待ちになることがある

GPU は1基を全員で共有しているため、SFT・DPO の学習を同時に走らせられる人数は限られています。枠が埋まっていると、学習セルに次のように表示されます。

```
[handson] GPU スロット（2本）が埋まっています。空くまで待機します...
```

そのまま待てば、枠が空いたときに自動で始まります。待っている間に次のセルの説明を読んでおきましょう。待つのをやめたいときは、ツールバーの ■（停止）ボタンを押してください。

ターミナルから学習スクリプトを実行するときは、JupyterLab のメニュー **File → New → Terminal** でターミナルを開き、次のように `gpu_queue.sh` を付けて実行します。

```bash
gpu_queue.sh python chapter2/scripts/train_sft.py
```

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| 手順 1 で `Connection closed by 10.1.3.220 port 22` や `kex_exchange_identification` と表示される | 会社の PC で実行していませんか。SSH は**貸与 VM の中で**実行してください。VM の中でも出る場合は講師に声をかけてください |
| ブラウザで「接続できません」と表示される | ① **VM の中のブラウザ**で開いているか確認してください（会社の PC のブラウザでは開けません）。② 手順 1 の SSH のウィンドウが開いたままか確認し、閉じていたら、もう一度実行します |
| 手順 1 で `bind [127.0.0.1]:8801: Permission denied` や `bind: Address already in use` と表示される | VM の中で、その番号がすでに使われています。① SSH のウィンドウを2つ開いていないか、② VS Code で DGX につないでいないか（VS Code が同じ番号を自動で転送していることがあります）を確認してください。どのプログラムが使っているかは、PowerShell の `netstat -ano \| findstr LISTENING \| findstr :8801` で末尾の番号を調べ、`Get-Process -Id <番号>` で確認できます。それでも解決しないときは、`-L 9801:localhost:8801` のように左側の番号を変え、ブラウザでは `http://localhost:9801/lab?token=...` を開いてください（8800 のときは `-L 9800:localhost:8800` と `http://localhost:9800/`） |
| 教材ページで数式が崩れる・リンクが開けない | JupyterLab の中で HTML を開いていないか確認してください。教材ページは `http://localhost:8800/` から開きます |
| 教材ページの見た目が崩れる（文字だけになる） | 教材ページは表示にインターネット上のライブラリを使います。VM のブラウザでほかのサイトが開けるか確認してください |
| 手順 1 で `Permission denied` と表示される | パスワードが違います。入力し直してください |
| 手順 1 でパスワードを入力したあと、何も表示されない | SSH コマンドに `-N` が付いていませんか。`-N` を付けると URL が表示されません（トンネルはつながっているので、運営から受け取った URL があればそのまま使えます） |
| 手順 1 で「JupyterLab の準備がまだできていません」「まだ起動していません」と表示される | 運営側の準備が終わっていません。講師に声をかけてください。SSH のウィンドウはそのままで構いません |
| 手順 1 で「参加者用の VM として登録されていません」と表示される | 割り当てられた VM とは別の VM から接続しています。講師に声をかけてください |
| 手順 1 で URL の日本語が文字化けする | URL（`http://` から始まる部分）は英数字なので、そのままコピーして使えます |
| ログイン画面（Password or token）が表示される | URL の `token=` の後ろの文字列を入力してください |
| 他の人のファイルが見えている・番号が違う | URL の番号が自分のものか確認してください |
| セルが終わらない・画面が固まった | ■（停止）ボタンを押し、それでも駄目なら **Kernel → Restart Kernel** を選んでください |
| それでも解決しない | 参加者番号を添えて講師に声をかけてください |

## 終了時

- 持ち帰りたいファイルは、ファイル一覧で右クリック → **Download** で保存してください。保存先は **VM の中**です。VM から会社の PC へ持ち出す場合は、会社の規程に従ってください。**ハンズオン終了後、サーバーは止まります**
- SSH のウィンドウは `Ctrl + C` で閉じて構いません
