## 3. 修正後の到達目標

読者が次のことを、自分の言葉と小さな計算で示せる状態を目指す。

1. Attention は、参考にする割合を計算し、その割合で複数の情報を集める処理だと説明できる。
2. Q は探す条件、K は照合する目印、V は受け渡す情報だと区別できる。
3. 一語について「内積 → スケール調整 → softmax → V の加重和」を追える。
4. 参考にする割合の表と、集めた情報の出力ベクトルが、別のものだと説明できる。
5. 割合の表を行ごとに読み、因果マスクで後ろの位置を使えなくする理由を説明できる。
6. Attention の出力が Transformer の処理を通り、次のトークンの予測に使われる流れを説明できる。

総合式の暗記や、実モデルのヘッド数の暗記は到達目標に含めない。

### 書き換え後の説明の調子

> 「太郎はリンゴを食べた。それは甘かった。」と読むと、「それ」はリンゴを指すと考えられます。「それ」という言葉だけを見て分かるのではなく、ほかの言葉を手がかりにしているのです。Attention も、ほかの言葉が持つ情報を集める処理です。どの情報を何割ずつ集めるかを計算し、その割合で情報を足し合わせます。
>
> ここから計算する模型は、「太郎はリンゴを食べた。それ」までを使います。人が全文を読んだときとは違い、後ろの「甘かった」は使いません。模型には、仕組みを見やすくするために、人が「食べ物の情報を探す」という条件を設定します。本物のモデルでは、このような条件を作る変換の重みも学習で決まります。
>
> たとえば、数字を二つ並べた情報に0.5を掛けるときは、二つの数字それぞれに0.5を掛けます。これを候補ごとに行って足すと、新しく集めた情報ができます。次に、この0.5などの割合をどう計算するかを見てみましょう。

「内積＝合い具合」のような短い説明だけで終わらせず、共通例の計算と、その結果の意味を対応づけて示す。

## 5. 共通の例文と計算例

### 5.1 一つの例文を最後まで使う

基本の例文は、ユーザー指定の **「太郎はリンゴを食べた。それは甘かった。」** とする。本文、手計算、自作コード、演習、動画をこの例文で統一する。

全文を `太郎 / は / リンゴ / を / 食べた / 。 / それ / は / 甘かった / 。` の10単位に区切る。実際の Llama のトークン分割とは異なる、手で区切った教材用の模型であると明記する。二つの「は」と二つの「。」は、表では位置番号も添えて区別する。

最初は「それ」の一行だけを読み、「それ」が「リンゴ」の情報を受け取る処理を追う。段階ごとの入力範囲を明示する。

- 一語の基本計算と最初の行列計算は、`太郎 / は / リンゴ / を / 食べた / 。 / それ` の前半7単位を使う。
- 因果マスクは、同じ例文の全文10単位を使う。「それ」の行では、後ろの3単位が使えなくなるので、前半7単位で計算した割合・出力と一致することを確認する。
- Multi-Head の説明も同じ例文を使い、「食べた」について「誰が食べた？」なら「太郎」、「何を食べた？」なら「リンゴ」の情報を集める模型を示す。

導入で人が全文から「それ＝リンゴ」と考えることと、模型で「それ」の Q を手で設定することを区別する。「甘かった」を先に読んで生成型 LLM の Q を作った、という説明にはしない。

本物の Llama の観察では、現行の英語例を活かす。その際は「実モデルの別の入力を観察する段階」と明示し、模型と共通する処理、学習済みの数値やトークン分割など異なる点を説明する。

### 5.2 標準の数値は、複数の情報が混ざるものにする

次を標準計算例の候補とする。表中の意味のラベルは、人が設定した模型のもの。

前半7単位を使い、「それ」の Q を `(0, 1)` と手で設定する。Q/K の数字の個数は2。K は照合用の「人・食べ物」の目印、V は受け取る「人・食べ物」の情報とする。同じラベルでも、K と V は別の役割・別の数値として見せる。

| 候補 | K | V | Q と K の内積 | √2で割った点数 | softmax 後の割合（概数） |
|---|---|---|---:|---:|---:|
| 太郎 | (1, 0) | (1, 0) | 0 | 0 | 9.9% |
| は | (0, 0) | (0, 0) | 0 | 0 | 9.9% |
| リンゴ | (0, 2) | (0, 1) | 2 | 約1.414 | 40.7% |
| を | (0, 0) | (0, 0) | 0 | 0 | 9.9% |
| 食べた | (0, 0) | (0, 0) | 0 | 0 | 9.9% |
| 。 | (0, 0) | (0, 0) | 0 | 0 | 9.9% |
| それ | (0, 0) | (0, 0) | 0 | 0 | 9.9% |

集まった情報は、丸める前の割合を使うと約 `(0.099, 0.407)` になる。この候補は Python 標準ライブラリで内積、softmax、加重和を計算し、数値を確認済み。

数値と表示には次のルールを設ける。

- 内部計算は丸めず、表示だけを丸める。上の一桁表示の合計は100.1%になるため、計算上は100%であり表示の丸めによる差だと注記する。
- 0点の候補にも、softmax 後は割合が付くことを見せる。マスクで使えなくした候補の0%との違いが説明できる。
- V が `(0, 0)` の候補は、この模型では足し合わせる情報も0だと示す。実モデルの助詞や句読点が情報を持たないという意味にはしない。
- 操作で直接指定した割合の体験と、Q/K から計算した割合の実験を、それぞれ表示上で区別する。
- 約99%に集中する旧例は、点数を大きくした比較実験として扱う。標準値から何を変えたかを示す。
- 実装前に、全位置の X、W、Q/K/V、マスク、出力までを確定し、HTML・ノートブック・動画が同じ条件で同じ数値を使う一覧を作る。前半7単位と全文10単位を区別し、入力範囲とマスクの有無を各図・計算例に添える。

### 5.3 図で固定するもの

- Q＝探す条件、K＝照合する目印、V＝受け渡す情報の色・名称をそろえる。色に加えて文字ラベルを必ず付ける。
- 「参考にしに行く向き」は `それ → リンゴ`、「情報が渡る向き」は `リンゴ → それ` と明記する。
- 計算する点数、参考にする割合、集まった情報を別の枠で表示する。
- 基本計算では、一語の割合は7候補ぶん、出力は2つの数字であることを見せる。全文10単位のマスク付きの表では、「それ」の後ろの3候補は0%になる。「割合の表がそのまま答えになる」という誤解を防ぐ。
- 全語の表には、行＝情報を受け取る側、列＝情報を渡す候補、行ごとの合計＝100%を併記する。

## 6. デモと実習の修正

既存のデモを利用し、基本の経路で案内する操作を絞る。印刷や動画を再生できない場面でも、静的な図と計算表で同じ説明を読めるようにする。

| 体験 | 変更するもの | 観察するもの | 理解してほしいこと |
|---|---|---|---|
| 割合を指定して集める | 二つの情報に配る割合 | 加重和の途中式と出力の数字 | 複数の情報を掛けて足すとはどういうことか |
| 探す条件を変える | 選択した一語の Q | Q/K の内積、割合、出力 | Q/K は参考にする割合を決める |
| 渡す中身を変える | 一候補の V。Q/K は固定 | 割合は同じで出力が変わる | K と V は役割が違う |
| 全位置を見比べる | 表の選択行 | 選択した位置の途中式 | Self-Attention は同じ処理を各位置で行う |
| 後ろを隠す | 因果マスクの有無 | 禁止位置の0%と、許可位置での再配分 | 後ろの答えを使わずに予測する |
| 発展の比較 | 点数の倍率、別ヘッド、自由編集 | 割合の集中、観点による変化 | 基本の仕組みを使って違いを調べる |

本編 Part 2 は、完成済みの実行・観察から始め、次に一語の途中計算、最後に行列でまとめた実装へ進む。W なしの失敗実験は、基本の処理を理解してから読む比較実験へ移す。

演習は、まず完成済みコードで結果を予想して観察し、その後に内積、softmax、加重和、マスクの穴埋めを行う。各操作に「何を変えるか」「どこを見るか」「何が分かったか」を短く添える。

## 7. 易しく説明するために、正確さも修正する

難しい補足を大量に増やすのではなく、該当する説明に短い限定や区別を入れる。

- **内積は向きだけで決まらない。** 長さも影響する。`(1, 0)·(1, 0)=1` に対して `(1, 0)·(2, 0)=2` なので、「自分との内積が必ず最大」と一般化しない。
- **Q/K/V は各層に入る表現から作る。** 最初の入力が埋め込みに基づくことと、後の層では前の層の処理結果を使うことを区別する。
- **模型の特徴名やヘッドの役割は人が決めたもの。** 本物の各次元が、そのまま「人」「食べ物」や、人間が読める質問を表すとは限らない。
- **Attention の出力は集めた情報。** 「それ」が「リンゴ」という単語に変わるわけではない。元の情報との足し合わせは、残差接続の段階で説明する。
- **割合は正解の確率ではない。** 参考にする割合と、最後に語彙へ割り当てる次トークンの確率を区別する。
- **並列計算と生成の順番を区別する。** 学習時は、既知の文をマスク付きでまとめて処理できる。通常の文章生成では、選んだトークンを追加し、その続きを予測する。マスクの三角形だけで逐次生成の理由を説明しない。
- **Attention の割合表だけで判断理由を断定しない。** 実モデルの観察は、入力・層・ヘッド・選び方を明示し、模型の意図どおりの結果が常に出るとは説明しない。
- **Attention Sink の説明を限定する。** 文頭への集中は観察例として示し、72%などの値には測定条件を付ける。大きい割合だけから「情報を全く使っていない」と決めつけない。
- **導入の LLM の説明を対象に合わせる。** 「このハンズオンで扱う文章生成型 LLM は、次のトークンを予測する」と表現し、あらゆるモデルの仕組みを一文で断定しない。

Q/K から割合を作り、その割合で V を加重和する処理と、マスク・Multi-Head の基本構造は原論文の定義に合わせる。[Attention Is All You Need, §3.1〜3.2](https://arxiv.org/html/1706.03762v7#S3)

割合表からモデルの判断理由を読み取る限界は、研究でも検討されている。初学者には「この図は、情報を集める処理の一部を見せている」と説明する。[Attention is not Explanation](https://arxiv.org/abs/1902.10186)

## 10. 修正後の確認と完成基準

### 数値・実行の確認

- 内積、スケール、softmax、加重和の途中値と結果が、本文・計算機・ノートブック・動画で一致する。
- 内部計算では行ごとの割合の合計が1になり、マスクで禁止した位置は0になる。表示の丸めと計算を区別する。
- Q/K を固定して V を変えた場合、割合が変わらず出力だけが変わる。
- 前半7単位と全文10単位の各入力について、`shape`、位置番号、ラベル、assert、付録の準備セルを確認する。単位数は入力から求め、旧例の4や5が固定値として残らないようにする。
- 全文10単位に因果マスクをかけた「それ」の行では、後ろの3単位の割合が0になり、前半7単位の基本計算と同じ出力になる。
- 模型の計算は CPU で実行して確認する。実モデルを扱う部分は既存の DGX 環境で確認し、実行できなかった範囲は未確認として記録する。
- 解答の自己チェックを通し、課題 2・3 の穴埋めが引き続き成立する。変更したセルに古い出力を残さない。

### 表示・導線の確認

- PC と幅の狭い画面で、数式、表、図、入力欄、ラベルを読める。
- キーボードでもデモを操作でき、結果が色だけに依存せず分かる。
- 印刷表示では、動画や操作がなくても、固定した例の処理を追える。
- 発展欄を開かなくても基本の説明が完結し、関連節へのリンク・クイズの採点が動く。
- 動画の字幕、本文のキャプション、ポスターに、古い例文や数字が残らない。

### 読解の確認

教材レビューでは、少なくとも次の5問に本文だけで答えられるかを確認する。

1. 「参考にする割合」と「集まった情報」は何が違うか。
2. 割合が0.25と0.75、Vが `(4, 0)` と `(0, 8)` なら、集まる情報はいくつか。期待する答えは `(1, 6)`。
3. Q/Kを変えずにVだけ変えると、何が変わり、何が同じか。
4. なぜ各位置が、その後ろのトークンを参考にできないようにするのか。次の位置の予測と結びつけて説明できるか。
5. 模型で設定した「食べ物を探す」数字と、本物の LLM が学習した数字は、どう違うか。

誤答には、答えだけでなく、どの計算や区別を見落としたかと、読み直す箇所を示す。可能であれば、実際の対象者に近い受講者や初学者に、講師の追加説明なしで読んでもらい、つまずいた用語・戻った箇所・所要時間を確認する。「高校生でもすんなり理解できる」という目標は、専門知識を補わなくても、身近な例とその場の説明だけで計算を追えるかを点検する基準として使う。

完成の判断は、**「太郎はリンゴを食べた。それは甘かった。」について、何を入力し、何を比べ、どんな割合になり、何が出力されたかを、本文・図・実行結果から一貫して追えること**を中心に行う。実際の受講者や初学者による読解確認を実施していない場合は、受講者が理解できることを検証済みとは記録しない。
