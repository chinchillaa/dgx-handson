読み始める前に

LLM がしているのは、
次に来る単語（トークン）を予測することだけです。

LLM は大量の文章を読んで、「この続きに来やすい単語は何か」を学びます。 文章を書くときは、次の単語を予測して 1 つ選び、それを付け足してまた予測する、という作業を繰り返しています。

この仕組みは、モデルがどれだけ大きく新しくなっても変わりません。 パラメータが数千億個のモデルも、考える過程を書き出すモデルも、画像や音声を扱うモデルも、中心にあるのは同じ「次の単語の予測」です。

LLM が人間のように考えているように見えるのは、 この単純な仕組みを、ものすごい量の文章で鍛えた結果です。 このページで学ぶ Attention や Transformer は、この予測を上手に行うための仕組みです。

前置き

言葉を「数字の並び」に置き換える

埋め込み（Embedding）は、単語を数字の並びに置き換える処理です。 コンピュータは文字のままでは計算できないので、AI が言葉を扱うには、まず言葉を数字にする必要があります。

埋め込みを学ぶと、次の 2 つの用語が登場します。

  • トークン：文章を区切った、AI が扱う単位です。おおむね単語や、単語の一部にあたります。
  • ベクトル：数字の並びのことです。たとえば (0.12, −0.84, 0.33) は 3 つの数字が並んだベクトルです。

文章が数字になるまでの流れ

文章
「リンゴを食べた」
→
トークンに区切る
「リンゴ」「を」「食べた」
→
番号にする
[3021, 12, 845]
→
ベクトルにする
[0.12, −0.84, …] × 3

番号は説明のための例です。 番号をベクトルにするときは、「番号ごとにベクトルを書いた大きな表」から、その番号の行を取り出します。 ハンズオン③で使う Llama-3.2-1B では、1 つのトークンが 2048 個の数字の並びになります。

意味の近い単語は、近い場所に置かれる

ベクトルは、地図の上の位置（座標）だと考えることができます。 AI は大量の文章から学ぶうちに、意味の近い単語ほど近い場所に置くようになります。

右の図は、2 つの数字だけで描いたイメージです。 「王様」と「女王」、「男性」と「女性」は、それぞれ横に同じだけずれた位置にあります。 この横のずれが「性別」の違いを表しています。

ベクトルの足し算・引き算で、意味を計算できる

$$\vec{v}(\text{王様}) - \vec{v}(\text{男性}) + \vec{v}(\text{女性}) \approx \vec{v}(\text{女王})$$

$\vec{v}(\text{王様})$ は「王様」のベクトルです。 王様から「男性」を引いて「女性」を足すと、女王のすぐ近くの位置になります。 言葉を数字にしたことで、意味の関係を足し算・引き算で扱えるようになったわけです。

解説動画：単語ベクトルの足し算・引き算で意味を計算する（約 30 秒）

4 単語の位置は上の図と同じです。 王様から男性を引いて女性を足すと、着地点が女王のすぐ近くに来ます。

もっと詳しく：埋め込みの表と、ベクトルにする理由

埋め込みの正体は、「語彙の数 × 次元数」の大きな表（行列）です。 トークンの番号を行の番号として使い、その行のベクトルを取り出します。 この表の中身も、ほかのパラメータと一緒に学習で決まります。

ニューラルネットワーク（NN）の計算は、すべて「行列の掛け算＋活性化関数」です。 テキストをベクトルにすると、言語の処理にも NN の計算をそのまま使えます。 Transformer はこのベクトルの列を受け取り、各ベクトルを文脈に合わせて作り変えていきます。

Section 1

Attention が生まれる前：RNN の弱点

単語をベクトルにしても、まだ「単語どうしの関係（文脈）」は分かりません。 Attention が登場する前は、RNN（再帰型ニューラルネットワーク）が文脈を扱っていました。 RNN は、単語を先頭から 1 つずつ順番に読み、それまでの内容を 1 つのメモにまとめて次へ渡す仕組みです。 このメモを隠れ状態と呼び、図の $h_1, h_2, \dots$ がそれにあたります。

RNN の読み方：メモを順番に渡していく

RNN には、伝言ゲームと同じ 2 つの弱点がありました。

弱点① 前のほうを忘れる

メモは何度も書き直されるので、文の最初の情報は、最後に届くころには薄れています。 「私は……（長い文）……食べた」の「私」と「食べた」を結びつけるのが苦手です。

弱点② 順番待ちで速くできない

$h_2$ を作るには $h_1$ が必要なので、1 単語ずつ順番に計算するしかありません。 同時にたくさん計算するのが得意な GPU を活かせず、長い文ほど時間がかかります。

Attention の解決策：全部の単語を直接見る

Attention は、メモを順番に渡しません。 各単語が、文の中のすべての単語を直接、一度に見に行きます。 そのため、遠くの単語も忘れず、全部の単語の計算を同時に進められます。 下の図は、「食べた」が各単語をどれくらい参考にするかを表したイメージです。

「食べた」が各単語を参考にする割合（イメージ）

「食べた」は、何を食べたかを表す「寿司」（0.45）と、いつ食べたかを表す「昨日」（0.28）を多く参考にします。 5 つの割合を足すと 1.00（100%）になります。 数値は説明のためのイメージです。

解説動画：RNN の順番読みと Attention の一括読み（約 24 秒）

上の段の RNN は、メモを $h_1$ から $h_5$ まで順番に作ります。 「私」の情報が薄れていく割合はイメージです。 下の段の Attention は、「食べた」から 5 つの単語への割合（上の図と同じ値）を一度に計算します。

もっと詳しく：Attention が生まれた経緯

固定次元のボトルネック：当時の翻訳モデル（Encoder-Decoder）は、入力文全体の意味を決まった長さのベクトル 1 本に押し込んでから翻訳を始めていました。 文が 5 単語でも 50 単語でも入れ物の大きさは同じなので、長い文ほど情報があふれ、翻訳の精度が下がることが報告されています（Cho et al., 2014／Bahdanau et al., 2014）。 「入れ物を大きくするのではなく、必要なときに元の文を見に行けばよい」という発想から生まれたのが Attention です。

勾配消失：RNN は学習のときも、誤差の情報（勾配）を何ステップもさかのぼって伝えます。 さかのぼるうちに勾配が小さくなるため、離れた単語どうしの関係を学びにくくなります。

原点は「翻訳の単語対応」：Attention が最初に提案されたのは、Transformer より 3 年前の 2014 年の機械翻訳の論文です（Bahdanau, Cho, Bengio）。 「あなたはアイリスですか」を "Are you Iris?" に訳すなら、you ←「あなた」、Iris ←「アイリス」、? ←「か」という対応があります。 出力する単語ごとに、入力のどこを見るべきかを重みで表したのが始まりです。 この論文のタイトルや主な用語は "align"（対応づけ）で、仕組みは主に「soft alignment（やわらかい対応づけ）」「soft search」と呼ばれています。 "attention" という言葉は、本文で仕組みを説明する箇所（"a mechanism of attention in the decoder"）に出てくる程度です。
Bahdanau et al., Neural machine translation by jointly learning to align and translate (arXiv:1409.0473)

Section 2

Attention：ほかのどの言葉を、どれくらい参考にするか

Attention は、ある言葉の意味を理解するとき、ほかのどの言葉を、どれくらい参考にするかを決める仕組みです。

人間も、同じ言葉を前後の言葉から理解しています。 たとえば「はし」は、「はしを渡る」なら「渡る」を参考にして「橋」だと分かり、「はしで食べる」なら「食べる」を参考にして「箸」だと分かります。 Attention は、この「参考にする」を計算で行います。

Attention について学ぶと登場する 2 つの用語

Self-Attention 同じ文章の中にある、単語どうしの関係を調べる仕組みです。LLM で使う Attention は、基本的にこれです。
Multi-Head Attention 複数の Attention を同時に使い、違う観点から単語どうしの関係を調べる仕組みです。

具体的には：割合を決めて、情報を混ぜる

具体的には、Attention は単語ごとに次の 2 つを行います。

  1. ほかの各単語を何 % 参考にするかを、合計が 100% になるように決めます。
  2. その割合に応じて、ほかの単語の情報を混ぜ合わせ、自分の情報に取り込みます。

例として、「太郎はリンゴを食べた。それは甘かった。」の「それ」を見てみます。 「それ」の意味を理解するには、何を指しているかを知る必要があります。 そこで「それ」は、前にある単語のうち「リンゴ」をほぼ 100% 参考にします。 その結果、「それ」は「リンゴのことだ」という情報を持つようになります。

「それ」が各単語を参考にする割合

太郎はリンゴを食べた。それ
0.2%0.2%99%0.2%0.2%0.2%0.2%

この割合は、あとの「数式」の節で実際に計算して求めます。 「それ」より後ろの「は・甘かった・。」は参考にしていません。理由は、この節の最後の「因果マスク」で説明します。

Multi-Head Attention の例：観点ごとに参考にする単語が変わる

1 つの Attention が調べられるのは、1 つの観点だけです。 そこで、観点の違う Attention（ヘッド）を複数並べます。 たとえば「それ」について、次のように役割を分けられます。

  • 「何を指しているか」を調べるヘッドは、「リンゴ」を参考にします。
  • 「誰の話か」を調べるヘッドは、「太郎」を参考にします。

各ヘッドの結果をまとめると、「それ」は「太郎が食べたリンゴ」という情報を持てます。

※ 各ヘッドの役割は説明用の例です。 実際のモデルでは、各ヘッドが何を受け持つかは学習で決まり、その役割が人間に分かる形ではっきり分かれているとは限りません。

Attention を数式で表すと

Attention を数式で表すと、次のようになります。 ここから先は、数字が並んだ表を行列と呼びます。

$$\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$
$Q$（Query） 各単語の「探しているもの」を表す数字です。例：「それ」は食べ物（物）を探しています。
$K$（Key） 各単語の「自分が何者か」を表す数字です。例：「リンゴ」は食べ物だと示しています。
$V$（Value） 参考にされたときに相手へ渡す情報です。
$QK^\top$ 「探しているもの」と「何者か」の合い具合です。$Q$ と $K$ の内積で計算します（$K^\top$ は $K$ の行と列を入れ替えたもので、全部の組み合わせの内積をまとめて計算するための書き方です）。
$d_k$ $Q$ と $K$ の数字の個数です。
$\sqrt{d_k}$ で割る 合い具合が大きくなりすぎないように小さくします。数字の個数が多いほど内積は大きくなりやすく、そのままだと 1 つの単語だけに割合が集中しすぎて、学習がうまく進まなくなるためです。
softmax 合い具合を、合計 100% の割合に直す計算です。合い具合が大きい単語ほど、大きな割合をもらいます。
$(\cdots)V$ その割合で $V$ を混ぜ合わせます（割合を掛けて足し合わせます）。

この式でいちばん大事なのは「内積 ＝ 合い具合」

高校で習うベクトルの内積は、2 つのベクトルの向きがそろっているほど大きな値になります。 直角なら 0、逆向きならマイナスです。 たとえば $(0, 3)$ と $(0, 3)$ の内積は $0 \times 0 + 3 \times 3 = 9$、$(0, 3)$ と $(3, 0)$ の内積は $0 \times 3 + 3 \times 0 = 0$ です。 Attention は、この性質を使って「探しているもの」と「何者か」が合っているかを測ります。

計算してみましょう：「それ」が「リンゴ」を 99% 参考にするまで

説明のため、$Q$ と $K$ を「人か」「食べ物か」の 2 つの数字だけで表します（$d_k = 2$）。 本物のモデルでは数字は数十〜数百個あり、値は学習で決まります。

ステップ 1：「探しているもの」と「何者か」を数字で表す

人か食べ物か説明
それ の $Q$03食べ物を探している
太郎 の $K$30人である
リンゴ の $K$03食べ物である
ほかの $K$00は・を・食べた・。・それ

ステップ 2：内積で合い具合を測り、$\sqrt{2} \approx 1.41$ で割る

内積÷ 1.41
太郎$0 \times 3 + 3 \times 0 = 0$0

ステップ 3：softmax で割合に直す

softmax は、各値 $x$ を $e^x$（$e \approx 2.718$）に変えてから、全体の合計で割ります。 $e^x$ は $x$ が大きいほど急に大きくなるので、合い具合の大きい単語に割合が集まります。

$e^x$割合（合計 586.5 で割る）
リンゴ$e^{6.36} \approx 580.5$$580.5 \div 586.5 \approx 0.99$（99%）
ほかの 6 単語$e^{0} = 1$（6 つ）$1 \div 586.5 \approx 0.002$（0.2%）ずつ

ステップ 4：割合に応じて $V$ を混ぜる

$V$ も「人か」「食べ物か」の 2 つの数字とし、太郎の $V$ を $(1, 0)$、リンゴの $V$ を $(0, 1)$、ほかを $(0, 0)$ とします。 割合を掛けて足すと、「それ」の新しい情報は $0.002 \times (1, 0) + 0.99 \times (0, 1) \approx (0.00, 0.99)$ になります。 「それ」に、リンゴの「食べ物である」という情報がほぼそのまま入りました。

Q・K・V はどこから来るのか

$Q$・$K$・$V$ は、どれも各単語のベクトル $X$（Section 0 の埋め込み）から作ります。 $X$ に、学習で決まる 3 つの行列 $W^Q$・$W^K$・$W^V$ をそれぞれ掛けて、$Q = XW^Q$、$K = XW^K$、$V = XW^V$ とします。 同じ単語のベクトルから、「探すとき用」「名乗るとき用」「渡すとき用」の 3 種類の数字を作り分けるイメージです。 Multi-Head Attention では、この 3 つの行列の組をヘッドの数だけ持ちます。

もっと詳しく：なぜ $W^Q$・$W^K$ が必要なのか

$Q$ も $K$ も同じ $X$ から作るなら、$W$ を掛けずに $Q = K = X$ でよいと思うかもしれません。 しかし、そうすると各単語は自分自身を最も参考にしてしまいます。 内積は向きがそろうほど大きくなるので、自分と自分の内積がいちばん大きくなりやすいからです。

ハンズオン③ Part 2-2 では「ネコ・が・サカナ・食べた」で実際に計算します。 $Q = K = X$ のままだと、「食べた」は目的語の「サカナ」（0.22）より自分自身（0.35）を多く参考にします。 $W^Q$・$W^K$ で「探すとき用」と「名乗るとき用」に作り分けると、「食べた」は「サカナ」を 0.99 参考にするようになります（Part 2-3）。

$W^K$自分のどの面を名札として見せるか
$W^V$参考にされたとき、何を渡すか
もっと詳しく：Attention は「あいまい検索できる辞書」

Key と Value という名前は、プログラミングの辞書（Python の dict）から来ています。 普通の辞書 d[q] は、q と完全に一致するキーを探し、その値だけを返します。一致しなければエラーです。

Attention は、q に似ているキーほど大きな割合をつけ、全部の値を割合に応じて混ぜて返します。 $q$ が $k_2$ にそっくりなら返ってくるのはほぼ $v_2$、$k_1$ と $k_2$ の両方に似ていれば $v_1$ と $v_2$ が半分ずつ混ざります。 つまり Attention は、完全一致の辞書を「あいまい検索できる辞書」に緩めたものです。 Attention の原論文が仕組みを「soft search」と呼んだのは、この意味です。

もっと詳しく：本物のモデルの Multi-Head Attention

ハンズオン③で使う Llama-3.2-1B は、1 層あたり 32 ヘッドで、それが 16 層あります。 モデル全体では 512 枚の「参考にする割合の表」を計算しています。

計算量を増やさないため、実装ではヘッドごとに大きな行列を別々に持ちません。 単語のベクトルの 2048 個の数字を 32 等分し、1 ヘッドあたり 64 個を担当させます。 ヘッドを 2 つ手で作って違いを見る実験と、この分割の実装は、ハンズオン③の付録 B にあります。

解説動画：Attention の計算を 1 ステップずつ追う（約 48 秒）

上の計算例を、同じ値で動かして見せます。 合い具合はリンゴが 9（÷√2 で 6.36）、ほかは 0 で、softmax で割合に直すとリンゴが 0.99 になります。 最後に、「何を指すか」のヘッド（リンゴを参考にする）と「誰の話か」のヘッド（太郎を参考にする）を並べます。 ハンズオン③ Part 2 では、同じ計算を「ネコがサカナを食べた」でコードにします。

文章を生成するときの約束：因果マスク（Causal Mask）

文章を生成するときは、まだ生成していない未来の単語を参考にしないようにする Causal Mask（因果マスク）という仕組みも使います。

Causal Mask は、各単語が自分より前の単語（と自分自身）だけを参考にできるように、後ろの単語を参考にする割合を 0% にする仕組みです。

理由は、LLM の学習が「次の単語を当てる」練習だからです。 後ろの単語が見えると、答えを見ながら答えを当てることになり、練習になりません。 文章を書くときも、まだ書いていない単語は存在しないので、前の単語だけで次を決める必要があります。

例文で確かめます。 「それ」は「リンゴ」より後ろにあるので、因果マスクをかけても「リンゴ」を参考にできます。 一方、文の最初の「太郎」は、後ろの「リンゴ」も「甘かった」も参考にできず、自分自身しか見られません。

因果マスク：自分より後ろは見えない

行が「参考にする側」、列が「参考にされる側」です。 ○の単語だけを参考にでき、×の割合は 0% になります。 ○が左下の三角形に並ぶので、この表は三角形の形になります。

計算では「softmax の前に $-\infty$ を入れる」

後ろの単語との合い具合を、softmax に入れる前に $-\infty$（マイナス無限大）に置き換えます。 $e^{-\infty} = 0$ なので、softmax で割合に直したとき、その単語の割合がちょうど 0% になります。

$$\text{合い具合}_{ij} = \begin{cases} \dfrac{q_i \cdot k_j}{\sqrt{d_k}} & (j \le i\text{：自分より前か自分}) \\[6pt] -\infty & (j > i\text{：自分より後ろ}) \end{cases}$$

$i$ は参考にする側の単語の位置、$j$ は参考にされる側の単語の位置です。 PyTorch では scores.masked_fill(~mask, float('-inf')) の 1 行で書けます。

LLM が左から右へ 1 単語ずつ書く理由

生成のときに 1 単語ずつしか進めないのも、文の最初の単語がほとんど文脈を持てないのも、この三角形の形から来ています。 ハンズオン③ Part 3 で因果マスクを実装し、割合の表が三角形になる様子を確かめます。

解説動画：因果マスクで後ろの単語への割合を 0 にする（約 43 秒）

上の計算例と同じ 7 単語で、後ろの単語の合い具合を $-\infty$ にしてから softmax を取ります。 「は」は、マスクなしでは 7 単語を約 0.14 ずつ参考にしますが、マスクありでは前の「太郎」と自分を 0.50 ずつ参考にします。 文の最初の「太郎」は自分自身しか参考にできず、「それ」はマスクがあっても前にある「リンゴ」を 0.99 参考にできます。 生成が進むと表の行が 1 本ずつ増え、新しい行は自分と前の単語しか参考にできません。

Section 3

Transformer ブロック：Attention を中心にした 1 セット

Transformer ブロックは、Attention と、そのほかの部品を組み合わせた処理の 1 セットです。 LLM は、このブロックを何十段も積み重ねてできています。 ハンズオン③の Llama-3.2-1B は 16 段です。

ブロックの入口と出口で単語ベクトルの形が変わらないので、何段でも積み重ねられます。 段を重ねるたびに、各単語のベクトルに文脈の情報が少しずつ書き足されていきます。

Transformer ブロックの中身

ブロックに登場する部品

Multi-Head Attentionほかの単語を参考にして、文脈の情報を取り込みます（Section 2 の内容です）。
FFN（Feed-Forward Network）各単語が、取り込んだ情報を自分だけで加工します。Attention が「どの単語を参考にするか」を受け持つのに対し、FFN は「受け取った情報をどう作り変えるか」を受け持ちます。
残差接続部品の出力を、入力に足し合わせます（$x + \text{Attention}(x)$）。元の情報を残したまま、変更分だけを書き足せるので、段を深く重ねても学習が安定します。
正規化ベクトルの数字の大きさをそろえます。段を重ねても数字が大きくなりすぎたり小さくなりすぎたりしないので、学習が安定します。
位置の情報Attention は、そのままでは単語の順番が分かりません（「ネコがサカナを食べた」と「サカナがネコを食べた」を区別できません）。そこで、各単語が文の何番目にあるかを別に教えます。
もっと詳しく：Llama で使われている部品の種類

正規化の位置（Post-Norm と Pre-Norm）：2017 年の原論文は、部品を通した後に正規化する Post-Norm（$\text{Norm}(x + \text{Attention}(x))$）でした。 しかし段を深く積むと学習が不安定になることが分かり、現在の LLM はほぼすべて Pre-Norm（$x + \text{Attention}(\text{Norm}(x))$）を使います。 Pre-Norm は、正規化してから部品に入れ、その結果を元の $x$ に足す方式です。 残差の通り道に正規化が挟まらないので、学習の信号（勾配）がまっすぐ下の段まで届きます。 上の図と、ハンズオン③の付録 C で組み立てるコードは、どちらも Pre-Norm です。

RMSNorm：Llama は正規化に RMSNorm を使います。 よく使われる Layer Normalization から「平均を引く」処理を省いた簡略版で、計算が軽いぶん速く動きます。 Layer Normalization は、バッチ正規化と違って各トークンのベクトルの中で正規化するので、文の長さが変わっても使えます。

FFN の大きさと SwiGLU：FFN は 2 層の線形変換で、途中の次元は通常 4 倍に広げます（Llama-3.2-1B なら 2048 → 8192 → 2048）。 活性化関数は ReLU や GeLU が一般的ですが、Llama は SwiGLU（SiLU とゲートの仕組みの組み合わせ）を使うので、線形層が 3 枚になります。 モデルのパラメータの大半を占めるのは、Attention ではなく FFN です（ハンズオン③の付録 C-1 で内訳を数えます）。

位置の情報（RoPE）：原論文は、sin と cos で作った位置のベクトルを埋め込みに足していました。 Llama は RoPE（回転位置埋め込み）を使い、Attention の計算の中で $Q$ と $K$ を位置に応じて「回転」させて位置を表します。

ハンズオン③ Part 4／付録 C：本物と見比べ、自分で組み立てる

Part 4 では、本物の Llama の 1 段を print() で表示します。 Part 2 で自分が書いた $W^Q$・$W^K$・$W^V$ が、 q_proj / k_proj / v_proj という名前でそのまま入っていることを確かめます。 o_proj、 input_layernorm、 mlp は、本編では「まだ作っていない部品」として眺めるだけです。 付録 C では、上の図の部品（正規化 → Multi-Head Attention → 残差 → 正規化 → FFN → 残差）を、 PyTorch の nn.Module で 50 行ほどで組み立てます。 自分で作ったものと本物の違いは、大きさと「学習済みかどうか」だけです。

Section 4

LLM へのつながり

LLM（大規模言語モデル）は、Transformer ブロックを何十段も積み重ね、次の単語の確率を出すように学習したモデルです。 Transformer は 2017 年の論文「Attention Is All You Need」で提案されました。 その後、Transformer の使い方の違いから、2 種類のモデルが広まりました。

Transformer の 2 つの使い方

文章を読んで理解する（Encoder-only）

BERT など

文章全体を前からも後ろからも読み、文の意味を表すベクトルを出します。 因果マスクを使わないので、後ろの単語も参考にできます。 文章の感情を判定するなど、分類が得意です。

入力 → [ブロック × N] → 意味のベクトル

文章を書く（Decoder-only）

GPT / Llama / Claude など

左から右へ、次の単語を 1 つずつ予測して文章を書きます。 因果マスクで、まだ書いていない後ろの単語を参考にしないようにしています。 いま LLM と呼ばれているものの多くはこちらです。

入力 → [ブロック × N] → 次の単語の確率

LLM が次の単語を決める式

$$P(\text{次の単語} \mid \text{これまでの単語}) = \text{softmax}(W \cdot h_n)$$
$P(A \mid B)$B が分かっているときに A が起こる確率です。ここでは「これまでの単語」から見た「次の単語」の確率です。
$h_n$最後のブロックが出力した、いちばん最後の単語のベクトルです。文全体の文脈が書き込まれています。
$W$$h_n$ から、語彙のすべての単語の点数を作る行列です。
softmax点数を、合計 100% の確率に直します（Section 2 と同じ計算です）。

確率に従って次の単語を 1 つ選び、文の最後に付け足して、また同じ計算をします。 これを繰り返して、1 単語ずつ文章を書いていきます。

なぜ LLM は賢いのか：大きくするほど賢くなる

Transformer ブロックを深く・広くし、大量の文章で次の単語の予測を練習させるだけで、翻訳・推論・プログラミングなどの能力が現れてきます。 この「大きくするほど賢くなる」関係をスケーリング則と呼びます（補足資料「事前学習」で詳しく扱います）。 ハンズオン③の Llama-3.2-1B は約 12 億パラメータで、MNIST で使った約 20 万パラメータの約 6,000 倍です。 GPT-4 のパラメータ数は公開されていません（1 兆規模とする推定はあります）。

  • 01埋め込みは、単語を数字の並び（ベクトル）に置き換える処理です。意味の近い単語は、近い位置に置かれます
  • 02Attention は、ある言葉を理解するとき、ほかのどの言葉をどれくらい参考にするかを決める仕組みです。「それ」は「リンゴ」を 99% 参考にして、「リンゴのことだ」と分かります
