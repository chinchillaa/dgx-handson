読み始める前に

LLM の知識そのものは、
誰も教えていません。

膨大なテキストから「次に来る単語」を当てる練習を、ただひたすら繰り返します。 それだけで LLM は、翻訳も、要約も、コーディングも、事実の記憶も身につけました。 しかも人間はラベルを 1 つも付けていません。

ハンズオン②の MNIST では、「この画像は 7 です」という正解を人が用意する必要がありました。 一方、事前学習ではテキストそのものが正解になります。 次の単語を隠せば、隠した単語がそのまま答えになるからです。 そのためインターネット上のあらゆる文章がそのまま教材になり、 学習データを人手で用意するコストがなくなりました。 LLM が桁違いに強くなれた理由は、アルゴリズムの工夫よりも先に、まずこの点にあります。

このページでは、この「ラベルのいらない学習」の仕組みと、 モデルをどれだけ大きくすればどれだけ賢くなるのかという法則を扱います。

このページで理解すること

  1. 事前学習が「ラベルなしで自己教師あり学習する」仕組みを掴みます
  2. 次トークン予測が教師信号をどのように自動生成するかを掴みます
  3. スケーリング則が示す、パラメータ・データ・計算量の 3 者の関係を掴みます
  4. 事前学習済みモデルを活用する方法の選択肢を掴みます

前置き

事前学習とは何か

ニューラルネットワーク（NN）の学習には「正解ラベル」が必要です。 線形回帰では正解値 $y$ が、MNIST 分類では手書き数字の正解クラスが必要でした。 しかし LLM の事前学習はラベルを一切用意せず、 テキストそのものから教師信号を自動生成します。

教師あり学習（これまで）

入力 $x$ と正解ラベル $y$ のペアが必要です。

画像 → ラベル「猫」「犬」
文章 → 感情「ポジティブ」

ラベル付けには人手が必要なので、大規模化にはコストがかかります

自己教師あり学習（事前学習）

テキスト自体から教師信号を自動生成します。

「猫が____」 → 正解「好き」
「今日の____は晴れ」 → 正解「天気」

インターネット上のテキストすべてが学習データになります

重要な視点

事前学習でモデルが学ぶのは、テキストの統計的なパターンです。 それでも大量で多様なテキストを学ぶうちに、推論・翻訳・コーディングといった能力が創発的に現れます。 この創発が LLM の能力の源泉です。

Section 1

次トークン予測（Causal Language Modeling）

GPT 系モデル（Decoder-only Transformer）の事前学習タスクは、とてもシンプルです。 それまでのトークン列を与え、次に来るトークンを予測します。 このタスクでは、1つの文章から複数の「問題」を自動的に作れます。

1文から複数の学習サンプルを自動生成

「 猫  が  窓  の  外  を  眺め  た 」
入力（コンテキスト） → 正解（次トークン）
「猫」 → 「が」
「猫」「が」 → 「窓」
「猫」「が」「窓」 → 「の」
「猫」「が」「窓」「の」 → 「外」
「猫」…「外」「を」「眺め」 → 「た」

8トークンの文から、7個の学習サンプルが自動生成されます。 ハンズオン③の付録 E-1 では、 logits の形が実際に (1, トークン数, 語彙数) になっていることを確認します。 この形から、モデルが全位置ぶんの「次は何か」を同時に出していることを目で確かめられます。 1兆トークンのデータセットなら、約1兆個の学習サンプルが得られます。

事前学習の損失関数

$$\mathcal{L} = -\frac{1}{T}\sum_{t=1}^{T} \log P(x_t \mid x_1, x_2, \ldots, x_{t-1};\, \theta)$$
$x_t$ 位置 $t$ の正解トークン
$x_1 \ldots x_{t-1}$ それまでのトークン列（コンテキスト）
$P(\cdot \mid \cdot;\,\theta)$ モデルが予測した確率分布（語彙サイズ分の softmax 出力）
$-\log P$ 交差エントロピー損失。正解トークンの確率を最大化する方向にパラメータを更新します

MNIST の分類で使った CrossEntropyLoss と本質的に同じです。 違いは、クラス数が「10クラス」から「語彙サイズ（数万〜数十万）」に増えた点だけです。

因果マスク（Causal Mask）

Decoder-only モデルは Attention の計算で、各トークンが自分より後ろのトークンを参考にする割合を 0% にします。 これを因果マスクと呼びます。 因果マスクがあるので、1 回の計算で文中のすべての位置について「次のトークン」の予測と答え合わせを同時に行え、 学習の効率が上がります。

マスクを外した場合、モデルは「次のトークン」をそのまま覗き見できます。 その結果、答えを見ながら答えを当てる練習になり、学習が成立しません。 仕組みと実装は 補足資料：Transformer の Section 2、および ハンズオン③ Part 3 を参照してください。

学習データ——何を、どれだけ学ぶか

事前学習の能力はデータの量・質・多様性に大きく依存します。 現代の LLM は数千億〜数兆トークンのテキストで学習されています。

データ品質は量より重要

Llama 3 の論文でも、データのフィルタリングと品質管理を重視したと述べられています。 同じ計算量なら、品質の高いデータで学習したほうが性能が上がる傾向が、複数の研究で報告されています（例: Microsoft の phi シリーズ、Hugging Face の FineWeb-Edu）。 量をただ増やすより、質の悪いデータを除くことが効く場合があります。

Section 3

スケーリング則——大きくするほど賢くなる

2020年に OpenAI が発見した「スケーリング則」は、LLM 開発の指針になっています。 この法則は、パラメータ数・学習トークン数・計算量を増やすと、損失が予測できる形で下がることを示します。

べき乗則（Power Law）

$$L(N, D) \approx \frac{A}{N^\alpha} + \frac{B}{D^\beta} + L_\infty$$
$N$ モデルのパラメータ数
$D$ 学習トークン数
$\alpha,\,\beta$ スケーリング指数（実験的に決定）
$L_\infty$ データ自体のノイズによる理論的最小損失

$N$ と $D$ のどちらを増やしても損失は下がります。 ただし、一方だけを増やすと効率が悪くなります。

Chinchilla 法則（2022年、DeepMind）

計算予算（FLOPs）を固定した場合、損失を最小化するには パラメータ数 $N$ とトークン数 $D$ の比率を約 1:20 に保つのが最適だと判明しました。

Chinchilla の発見以降、LLaMA や Mistral などの効率的なモデルが次々に登場しました。 現在の主流は「小さいパラメータ＋大量データ」の設計で、推論コストを下げながら高い性能を実現しています。

Section 4

事前学習済みモデルの活用方法

事前学習には莫大な計算資源が必要なので、 ほとんどの実務では事前学習済みモデルを出発点として活用します。 活用のアプローチは3つあり、目的・予算・性能要件に応じて使い分けます。

① プロンプトエンジニアリング
追加学習なし

モデルには一切手を加えず、入力の書き方だけで出力の質を上げるアプローチです。
最も手軽で、追加コストもゼロなので、まずはここから試すのが原則です。 代表例は、次の表の2つです。

使い方 内容
ゼロショット 例を示さず、指示だけを書きます。「このメールを要約してください」のように、自然言語で指定するだけです
Few-shot 入出力の例を数件（2〜10 件）示して、タスクを定義します。モデルは例からパターンを読み取ります

適用場面: 汎用タスク・プロトタイピング・出力形式を揃えたいとき。
注意点: 例を増やすほど、コンテキスト長とトークン課金を消費します。 例を何十件も並べたくなったら、ファインチューニングを検討するタイミングです。

② ファインチューニング（SFT / LoRA）
追加学習あり

タスク固有のデータでパラメータを更新し、特定ドメインへの適応力や指示への応答能力を強化します。 LoRA（Low-Rank Adaptation）を使えば、更新するパラメータを全体の 1% 以下に絞れます。

適用場面: 社内文書・専門用語・特定スタイルへの適応。第2章のメインテーマです。

③ RAG（検索拡張生成）
追加学習なし

質問に関連する文書をベクトル検索で取得し、コンテキストとしてプロンプトに挿入します。 モデルのパラメータを変えずに、「最新情報」や「社内知識」を参照させられます。

適用場面: 知識ベースを頻繁に更新するとき・ハルシネーションを抑えたいとき。第2章のメインテーマです。
