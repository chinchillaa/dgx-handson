# 参加者向け 接続手順書

このハンズオンでは、DGX（NVIDIA DGX Spark）1台を最大10人で共有します。
環境構築は不要です。運営側で1人1つずつ JupyterLab を用意しているので、手元の PC から SSH でつないで、ブラウザで開くだけで始められます。

## 事前に用意するもの

- **SSH が使える PC**
  - Mac / Linux: 標準のターミナルでそのまま使えます
  - Windows 10 / 11: PowerShell またはコマンドプロンプトで `ssh` が使えます
- **ブラウザ**（Chrome / Edge / Firefox / Safari）
- **運営から受け取る情報**（1人ずつ異なります）

| 項目 | 例 |
|---|---|
| 参加者番号 | `p01` |
| SSH コマンド | `ssh -N -L 8801:localhost:8801 -L 8800:localhost:8800 handson@10.1.3.220` |
| JupyterLab の URL | `http://localhost:8801/lab?token=xxxxxxxx` |
| 教材ページの URL | `http://localhost:8800/`（全員共通） |
| SSH のパスワード | 運営から別途お知らせします |

> **URL（トークン）は自分専用です。** 他の人には教えないでください。知られると、あなたの JupyterLab を他の人が開けてしまいます。

---

## 接続手順

### 1. SSH トンネルを張る

手元の PC でターミナル（Windows は PowerShell）を開き、受け取った SSH コマンドを実行します。

```bash
ssh -N -L 8801:localhost:8801 -L 8800:localhost:8800 handson@10.1.3.220
```

`-L` が2つあるのは、JupyterLab（8801。番号は人によって違います）と教材ページ（8800。全員共通）の2つをつなぐためです。

- 初めて接続するときは `Are you sure you want to continue connecting (yes/no)?` と聞かれるので、`yes` と入力します
- パスワードを入力したあと、**何も表示されずに止まったように見えますが、それで成功です**
- **このウィンドウはハンズオンの間ずっと開いたままにしてください。** 閉じると接続が切れます

### 2. ブラウザで開く

受け取った URL をブラウザで開きます。

```
http://localhost:8801/lab?token=xxxxxxxx
```

JupyterLab が開き、左側に `chapter1` `chapter2` `chapter3` のフォルダが表示されれば準備完了です。

### 3. 教材ページを開く

ブラウザの別のタブで、次の URL を開きます。講義の説明や補足資料はここで読みます。

```
http://localhost:8800/
```

> 教材ページは JupyterLab の中では開けません（JupyterLab の中で HTML を開くと、数式やリンクが正しく表示されないためです）。必ずこの URL から開いてください。

### 4. ノートブックを開く

JupyterLab の左側のファイル一覧から、講師の指示に従ってノートブック（例: `chapter1/notebooks/ch1_01_linear_regression.ipynb`）を開きます。カーネルは自動で選ばれるので、選ぶ必要はありません。

---

## VS Code を使っている場合

VS Code の Remote-SSH で `handson@<DGX のアドレス>` に接続し、「ポート」タブで自分の番号のポート（例: `8801`）と `8800` を転送すれば、手順 1 の代わりになります。
VS Code が別の番号に転送した場合は、URL の番号をその番号に読み替えてください。

---

## ハンズオン中のルール

- **自分の番号のフォルダ以外は触らないでください。** 全員が同じアカウントを使っているため、他の人のファイルを消せてしまいます
- **パッケージのインストール（`pip install` など）はしないでください。** 環境は全員で共有しています。必要なものはすべて入っています
- **モデルのダウンロードはできません。** 使うモデルは運営側で準備済みです。教材にないモデルを使いたいときは、講師に相談してください

## 知っておくと安心なこと

### ブラウザを閉じても、SSH が切れても大丈夫

ノートブックはサーバー側で動いているので、ブラウザを閉じたり SSH が切れたりしても、作業内容と実行中の処理は残ります。手順 1〜2 をやり直せば、続きから再開できます。

### 30分放置するとカーネルが止まる

30分何も実行しないと、メモリを空けるためにカーネルが自動で止まります。ファイルは残りますが、変数は消えます。「`NameError: name 'model' is not defined`」のようなエラーが出たら、**セルを上から実行し直してください。**

### 1人あたりのメモリには上限がある

他の人の作業を止めないよう、1人あたりのメモリには上限があります。

- `OutOfMemoryError` が出たら、メニューの **Kernel → Restart Kernel** でカーネルを再起動し、batch size などを小さくして実行し直してください
- カーネルが突然止まった（「Kernel Restarting」と表示される）ときも、メモリの使いすぎが原因の可能性があります

### 第2章の学習は順番待ちになることがある

GPU は1基を全員で共有しているため、SFT・DPO の学習を同時に走らせられる人数は限られています。枠が埋まっていると、学習セルに次のように表示されます。

```
[handson] GPU スロット（2本）が埋まっています。空くまで待機します...
```

そのまま待てば、枠が空いたときに自動で始まります。待っている間に次のセルの説明を読んでおきましょう。待つのをやめたいときは、ツールバーの ■（停止）ボタンを押してください。

ターミナルから学習スクリプトを実行するときは、JupyterLab のメニュー **File → New → Terminal** でターミナルを開き、次のように `gpu_queue.sh` を付けて実行します。

```bash
gpu_queue.sh python chapter2/scripts/train_sft.py
```

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| ブラウザで「接続できません」と表示される | 手順 1 の SSH のウィンドウが開いたままか確認してください。閉じていたら、もう一度実行します |
| 手順 1 で `bind: Address already in use` と表示される | 手元の PC で、その番号がすでに使われています。`-L 9801:localhost:8801` のように左側の番号を変え、ブラウザでは `http://localhost:9801/lab?token=...` を開いてください（8800 のときは `-L 9800:localhost:8800` と `http://localhost:9800/`） |
| 教材ページで数式が崩れる・リンクが開けない | JupyterLab の中で HTML を開いていないか確認してください。教材ページは `http://localhost:8800/` から開きます |
| 教材ページの見た目が崩れる（文字だけになる） | 教材ページは表示にインターネット上のライブラリを使います。手元の PC がインターネットにつながっているか確認してください |
| 手順 1 で `Permission denied` と表示される | パスワードが違います。入力し直してください |
| ログイン画面（Password or token）が表示される | URL の `token=` の後ろの文字列を入力してください |
| 他の人のファイルが見えている・番号が違う | URL の番号が自分のものか確認してください |
| セルが終わらない・画面が固まった | ■（停止）ボタンを押し、それでも駄目なら **Kernel → Restart Kernel** を選んでください |
| それでも解決しない | 参加者番号を添えて講師に声をかけてください |

---

## 終了時

- 持ち帰りたいファイルは、ファイル一覧で右クリック → **Download** で手元に保存してください。**ハンズオン終了後、サーバーは止まります**
- SSH のウィンドウは `Ctrl + C` で閉じて構いません
